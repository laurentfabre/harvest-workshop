Jeu pédagogique au format ERES. Les identifiants, personnes, montants et dates ont été adaptés. « Publiée » désigne une situation présente dans la vue Gold de l’atelier.

1 · Ouvrir votre essai

Ouvrez votre essai Harvest ou Avanade / Accenture avec votre compte. Importez votre copie du notebook et utilisez le code personnel affiché dans Mon parcours. Vous obtenez ainsi votre propre schéma, même si plusieurs personnes utilisent le même catalogue.

Préparer mon essai pas à pas →

  1. Dans votre essai Databricks, ouvrez Catalog. Choisissez un catalogue d’atelier où vous pouvez créer un schéma, puis un schéma contenant un volume géré où vous pouvez lire et écrire. Si nécessaire, le propriétaire de l’essai crée ce volume via Create → Volume.

  3. Dans Workspace → Import, importez import_eres.py comme notebook. Ouvrez-le sur un compute Python compatible avec les volumes. Exécutez la première cellule pour créer les widgets puis renseignez archive et equipe (votre code personnel affiché dans Mon parcours). Exécutez la cellule suivante. Relevez l’identité et le schéma affichés.

Si le catalogue, le volume ou le compute manque, le propriétaire de cet essai prépare la ressource. Les liens de Genie et Builder doivent provenir du même workspace. En attendant, ouvrez le petit ZIP localement et vérifiez la ventilation de la position à la ligne 5 de POS.

2 · Suivre les positions du lot

Exécutez Bronze et ouvrez bronze_pos. Choisissez une ligne et gardez le nom du fichier et son numéro. Remontez du sous-contrat au compte et au client, puis du support au référentiel TYP. Conservez la valeur brute du fournisseur.

Dans Silver, le lot porte la date du nom de l’archive. Un compte actif accepte une date de valorisation comprise entre le jour du lot moins trois ans et le jour du lot, bornes incluses. La ventilation doit vérifier disponible + indisponible = brut. Pour cet exercice, l’écart bloque la position. Silver conserve le premier motif bloquant.

Exécutez les vues Gold. Parmi les lignes valides de chaque compte, gardez toutes les positions à la dernière date valide. Une ligne valide plus ancienne devient historique. Un compte peut avoir plusieurs supports le même jour.

Vérification indépendante dans SQL

Dans SQL Editor, sélectionnez le catalogue et le schéma affichés par le notebook. Comparez les résultats suivants à bilan_lot.

SELECT (SELECT count(*) FROM bronze_pos) AS lues,
       (SELECT count(*) FROM gold_situation) AS publiees,
       (SELECT count(*) FROM revue_positions WHERE decision = 'HISTORIQUE') AS historiques,
       (SELECT count(*) FROM silver_positions WHERE regle <> 'VALIDE') AS rejetees;
SELECT fichier, ligne_csv, valeur_euro, disponible, indisponible
FROM silver_positions WHERE disponible + indisponible <> valeur_euro;
SELECT code_contrat, date_valorisation, decision
FROM revue_positions WHERE code_sous_contrat = 'SC-000001'
ORDER BY date_valorisation;
